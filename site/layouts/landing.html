01 why

The agent keeps working. You keep your terminal.

Agents run for hours. Laptops sleep, networks change, and hosts reboot. {{ $name }} keeps each agent in a session on a machine you own, and puts its real screen back in your terminal whenever you want it.

❯ new my-vps --agent claude
  ✓ started claude in a session

Any agent

Claude Code, Codex, opencode, Antigravity CLI, or any program that runs in a terminal. Agents are rows in a table, not code paths.

● homelab       4ms  ⣀⣠⣴⣶⣦⣄⣠⣴
● gcp-dev      38ms  ⣀⣀⣠⣶⣦⣀⣀⣠
◌ hetzner-box  offline  ⣀⣀⣀⣀⣀⣀⣀⣀

Your own hosts

Any host you reach with ssh: a VPS, a cloud VM, a machine at home. It uses your OpenSSH and your ~/.ssh/config. Nothing new listens on the host. No relay, no account.

kitty keys  shift+enter
host        1b 5b 31 33 3b 32 75
you         1b 5b 31 33 3b 32 75 ✓ same bytes

Byte for byte

No re-rendering and no multiplexer in the way. The kitty keyboard protocol, truecolour, links, the clipboard and notifications pass straight through. Your terminal's own scrollback and search keep working.

⣀⣠⣴⣶⣦⣄⣀⣀⣀⣀⣠⣶⣿⣦
✓ back: replayed 18 KiB you missed

Survives sleep and reboots

Close the laptop, change networks: the client reconnects by itself and replays exactly the output you missed. After a host reboots, each agent comes back with its own resume command.

02 how it works

Your ssh, a small helper, one process per session.

There is no daemon on the laptop and no central service on the host. The client speaks to a helper over your own OpenSSH. Each session is one holder process that owns the agent's terminal and keeps its output.

03 quick start

Three commands to your first session.

You need a Mac or a Linux machine, and a Linux host that ssh my-server logs you in to.

  1. 1 Install the client

    {{ $install }}

    It checks the release's signature and checksum, then puts {{ $name }} in ~/.local/bin. Other ways

  2. 2 Connect a host

    {{ $name }} host add my-server

    It checks that the host answers, installs a small helper in your home folder, with nothing that listens, and saves the host. No host yet? host create lima makes a local VM. Add a host

  3. 3 Start an agent

    {{ $name }} new my-server --agent claude --dir ~/src/app

    The agent owns your terminal. Ctrl+\ detaches, and the session keeps running. Run {{ $name }} to open the launcher and jump back in.

05 how it compares

Four things at once.

Many tools keep an agent working while your laptop is closed. {{ $name }} is for when you want all four of these together. Our research found no other tool with all four.

  1. ✓ Any agentrows in a table, not code paths
  2. ✓ The real terminal UIno multiplexer or web page re-draws it
  3. ✓ Sessions that lastthrough sleep, a new network and a reboot
  4. ✓ Your own machinesany host with ssh; no account, no relay, no open port

tmux, Zellij, screen

✕ They re-draw the screen, so your terminal's scrollback and search find nothing, and their prefix keys clash with the agents'. No status, no resume after a reboot.

→ Choose one for split panes on the host.

zmx, Eternal Terminal, mosh

✕ zmx and Eternal Terminal lose their sessions when the host reboots, and do not manage agents. mosh has no kitty keyboard protocol and no scrollback.

→ Choose mosh for a very slow or lossy link.

Hosted agents

✕ One vendor's agent, in the vendor's interface, on the vendor's machines. Several cap session length or need a paid plan for background work.

→ Choose one to start tasks from a phone or a browser, or to share them with a team.

Cloud development environments

✕ Workspaces stop when idle, and a session needs tmux to survive a disconnect, which brings the multiplexer's limits back.

→ Choose one when a team needs shared templates, access control and audit.

Where {{ $name }} is behind

  • No phone or web client: you answer from a terminal, though an alert can reach your phone.
  • No sharing: a session belongs to one user on the host.
  • You bring the host, or make one with host create.
  • Not released yet.
